1. Detection happens in Trampoline::doSomething() which calls getWorld()->getLemmingAt(getCoord().x, getCoord().y) in StudentWorld to find if a lemming exists at the same position as the trampoline. If a lemming is found and not already in a state of bouncing, the trampoline changes the lemming's state to bouncing, resets bounce variables, and plays bouncing sound. Later, that lemming’s doSomething() runs and executes the bouncing branch: it attempts moveUp() each tick, detects apex or target reached, then moves horizontally and switches to falling.
2. getActorAt() return only the first matching actor, so co‑occupant detection can miss tools when a lemming is stored earlier in m_actors. Actor update timing is order‑dependent (vector iteration in move()), causing inconsistent same‑tick reactions (icemonster kills, trampoline launches). Other issues: Bonfire lacks animation because increaseAnimationNumber() isn’t called because it fails the g32 sanity check (something about it being private? which should not be the case but I don't know).
3. I used a single vector<Actor*> m_actors and iterate it each tick. This kept implementation simple but made interaction timing depend on insertion order. Tool placement is blocked when a tile isn’t Blocking motion (i.e. not a floorblock), i.e., tools cannot be placed under existing actors. I diversify actor finders from getActorAt(), adding specific constraints for example for getAttractorAt() for phermones and getLemmingAt() for lemmings. This was so that actors can easily check for overlap (such as Ice Monsters and Lemmings).
